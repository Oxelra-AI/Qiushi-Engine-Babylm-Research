## Evidence now fixed

The completed cross-view experiment tested whether a true paired visible target helps when the predicted source-side anchors are identical in adjacent and shuffled arms. It did not show a stable true-pair benefit.

Cross-view adjacent minus shuffled:

Supervision identity was verified under the corrected invariant:

- seed42: 10,462 pair rows + 3,125 official rows, ok
- seed43: 10,469 pair rows + 3,125 official rows, ok

This closes the current version of the WikiAuto active-pair-use route: source-side exact-overlap anchor prediction with a true visible simplification does not produce a reliable Entity/EWoK gain over shuffled visible text.

Earlier WikiAuto results remain informative but narrow:

- pure pair adjacency: EWoK +1.275, Entity +0.685, but weak absolute BLiMP/Supplement/Reading and lower than official WWM on absolute Entity;
- 50/50 passive mixture: EWoK -1.64, Entity +0.365, broad columns not improved;
- active cross-view mixture: EWoK -0.69, Entity +0.085, no useful true-pair signal.

The robust conclusion is not that all structured data is useless. It is that **WikiAuto adjacency/anchor-copying is not the missing mechanism** for the current SOTA gap.

## Hidden signal that should not be overread

Cross-view models had better absolute BLiMP and Reading than the mixture adjacent vs shuffled 1m profile standard mixture, but this appeared in both true-pair and shuffled arms. Therefore any such effect, if real, comes from the anchor-targeting objective or code path rather than true paired semantics. It is not enough to justify scaling. It may later deserve a same-materialization three-arm comparison: standard WWM vs shuffled cross-view vs true cross-view, with matched token positions and several seeds.

For now, the larger unresolved gap is Entity Tracking: internal scores remain around 16–18 while the visible top row reports 28.45. A route that only explains small BLiMP/Reading movement is not the strongest next move.

## Rules and data latitude

Official source passages and official rules and landscape notes support custom data and closed-system generated/procedural data under the word budget. Text generated by a legal hand-coded generator can be used if all generated words count toward the 10M corpus budget and exposure budget, and all generation templates/seeds/word counts are recorded. External language-model outputs or tools trained on extra language data would require budget accounting and should not be used here.

This makes a hand-coded procedural state curriculum compliant if it is documented and counted.

## Next high-value route: 90/10 procedural entity-state stories

The next experiment should test whether explicit entity-state transition structure can transfer to official Entity Tracking/EWoK while avoiding the large distribution damage of 50/50 WikiAuto replacement.

Data composition at 1M exposure:

- 900k official BabyLM corpus examples;
- 100k hand-coded procedural entity-state microstories.

Base remains fixed:

- BERT 8x256;
- baseline 16k tokenizer;
- fixed 256 length;
- WWM base objective;
- exact 1M word exposure, paired seeds 42/43, same initialization/RNG convention;
- no DeBERTa, no 40k tokenizer, no LAMB, no length schedule, no 10M scaling.

### Story mechanism

Each story should contain 2–4 entities and a small set of state variables such as location, possession, containment, attribute, or relation. It should include one or more state updates plus distractor events. The masked target should be a final state value whose answer is determined by the last relevant update, not by local word repetition alone.

Example pattern, not to copy from evaluation data:

> Ava placed the marble in the red box. Ben moved the key to the tray. Later Ava moved the marble to the basket. The marble is now in the [MASK].

Include counterfactual matched variants so changing the decisive event changes the correct state value.

### Required arms

1. `official_wwm_matched`: 1M official-only WWM with the same 98-update geometry if existing official WWM is not geometrically matched.
2. `state_coherent_90_10`: 900k official + 100k coherent state stories, state targets masked inside a fixed mask budget.
3. `state_corrupted_90_10`: same templates, names, objects, locations, state values, word counts, answer target multiset, mask positions, update counts, and story lengths as the coherent arm, but entity bindings or decisive state assignments are permuted so the visible events no longer support the original target.

The central comparison is coherent minus corrupted. Official-only tells whether the 10% replacement introduces distribution tax or net gain.

### Controls

- Generated words count exactly toward the 1M and later 10M budgets.
- No use of official Entity Tracking items or text for training.
- Record generator code, random seeds, template families, vocabulary lists, story JSONL, word counts, token summaries, and source mix.
- Match total selected tokens/groups and state-target token budgets across coherent and corrupted arms.
- Keep official examples identical between coherent and corrupted arms for each seed.
- Save a held-out procedural probe generated from disjoint templates/vocab combinations; use it only for analysis, not for selecting by official Entity alone.

### Useful outcome pattern

The route becomes promising if coherent beats corrupted on official Entity in both seeds, does not harm EWoK/Supplement/Reading relative to corrupted, and also improves the held-out procedural state probe, especially with more state updates and distractors.

If coherent and corrupted both beat official similarly, the effect is entity density/simple language rather than state transition structure; then official-data resampling or official-only semantic masking becomes the better route. If neither beats official and the held-out procedural probe is weak, the current BERT-WWM backbone may need an explicit state/memory architecture rather than more structured text.

## Secondary route to keep in reserve

A same-materialization three-arm target-objective test can later clarify whether the cross-view anchor objective itself has a true general regularization effect:

- mixture adjacent vs shuffled 1m profile standard WWM rerun on the same materialization;
- shuffled cross-view;
- true cross-view.

This is lower priority than the procedural entity-state route because it does not directly explain the large Entity gap and the true-pair benefit already failed.
